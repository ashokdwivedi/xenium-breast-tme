Overview

Mapping the tumour microenvironment in Xenium in situ data

A reproducible, tested pipeline from raw 10x Xenium output to spatial statistics on the tumour–immune interface.

This is a complete, reproducible analysis of a public 10x Genomics Xenium In Situ run on FFPE human breast cancer: two replicate sections of the same tumour block, taken from raw vendor output through quality control, cell typing against a single-cell reference, and spatial statistics on how the tumour and immune compartments are arranged relative to each other. Everything here — the code, the thresholds, the unit tests, the figures and the tables behind every number on this site — is in the repository, and the whole thing reruns from a clean clone with bash scripts/download_data.sh && make all.

What the analysis shows

Three findings carry the story, and each is a link to the page that derives it.

  1. Both runs are technically sound, and the evidence is quantitative rather than visual. Negative-control probe rates are 0.038–0.088% of panel signal, median depth is identical at 164 transcripts per cell in both sections, and pseudobulk expression across the 313 panel genes correlates at r = 0.992 between replicates. The spatial structure that is present in the QC metrics tracks tissue architecture, not instrument geometry — which is the distinction that decides whether you filter cells or re-run the slide. See the QC page.
  2. Cell typing on a 313-gene panel is reliable for broad lineages and honest about where it stops. Label transfer from the Wu et al. breast-cancer atlas assigns 97.8% of QC-passing cells above a confidence floor, and an independent marker-scoring route agrees with it on 78% of clusters. The disagreements are reported, not smoothed over. See the cell-typing page.
  3. The tissue is compartmentalised, and the tumour boundary is selectively permeable. Against a label-permutation null that holds every cell position fixed, Normal Epithelial is the population most enriched within 30µm of the tumour compartment (log2 1.33), while B-cells is the most excluded (log2 -1.57). See the spatial page.

Why it was built this way

Three choices distinguish this from a notebook walkthrough, and each one exists because the alternative fails in production.

Thresholds are configuration, not folklore. Every QC cutoff lives in config/config.yaml and is written into the output tables alongside the verdict it produced. When a criterion is later judged too strict, the change is a one-line diff with a visible blast radius, not an archaeology exercise across notebook cells.

Both replicates are analysed, not just the prettier one. A single section cannot distinguish a biological gradient from a slide-level artefact. Two sections of the same block can, and the cross-replicate comparison is reported as a first-class result rather than a supplementary figure.

Cell typing is run twice, by independent routes, and the disagreement is published. Reference transfer and marker scoring fail in different ways: transfer inherits the reference's composition bias, marker scoring inherits the panel's blind spots. Where they agree the call is solid; where they do not, the honest output is a flag, not a label.

Note

The repository is tested. 21 unit tests run on synthetic fixtures in CI on every push — no data download required — covering the QC flags, the Moran's I statistic, niche recovery, the interface null model and the marker-ambiguity rule. A statistical function that cannot be tested on data with a known answer is a function nobody should trust.
