About

About this project

Why it was built, who built it, and how to get in touch.

This project is a self-contained demonstration of how I approach spatial transcriptomics data: start from the public raw output rather than a processed object, make the quality criteria explicit before looking at the result, run the annotation twice by independent routes, and state plainly what the data cannot support.

Why these three stages

They are the stages where spatial analyses actually go wrong. QC on in situ data is unforgiving — a background rate or a segmentation artefact propagates silently through everything downstream, and by the time it surfaces it looks like biology. Cell typing on a targeted panel is a judgement call that a pipeline cannot make for you: the panel sets a hard ceiling on resolvable identity, and pretending otherwise produces confident labels on evidence that does not exist. And spatial statistics is where a weak null model turns tissue geometry into a false discovery; permuting labels while holding positions fixed is the minimum defensible choice, and it is not the default in most published analyses.

What is in the repository

  • src/xtme/ — a small library: readers, QC, annotation, spatial statistics and a shared figure style. Every statistical function is importable and tested.
  • scripts/ — four numbered stages plus the download script. Each writes its tables and figures and nothing else.
  • config/config.yaml — every threshold and parameter in the analysis.
  • tests/ — unit tests on synthetic fixtures with known answers, run in CI on every push without any data download.
  • results/ — the figures and tables behind every claim on this site, committed so the repository is readable without running anything.

Reusing it

The pipeline is parameterised on the config file, so pointing it at a different Xenium run means editing paths and, if the tissue differs, swapping the marker sets in src/xtme/annotate.py and the reference in the config. The QC and spatial modules are tissue-agnostic.
